# 공백 (BLANK) — Godot 4

웹 프로토타입(`../parry/`)으로 검증한 패링 특화 원히트 액션을 Godot 4.x(GDScript)로 다시 만드는 프로젝트. 시우 공방.

## 열기 / 실행
1. Godot **4.5 이상** (TileMapLayer 사용 → 최소 4.3, 4.5.1 에서 확인)으로 `blank/project.godot` 를 연다.
2. 처음 열면 에디터가 `art/`, `sounds/` 를 자동으로 임포트한다 (`.godot/` 캐시는 git 에 넣지 않음).
3. F5 (프로젝트 실행) → `scenes/Boot.tscn` ("시우 공방" 로고 2초 → 게임). `Main.tscn` 만 따로 실행(F6)해도 된다 (로고·스캔라인 없이 창 크기 그대로).

## 프로젝트 설정 (project.godot)
| 항목 | 값 |
|---|---|
| 게임 화면 | 480 × 270 (`Boot.tscn` 의 SubViewport) |
| 창 크기 | 1920 × 1080 (window override) |
| 확대 | 게임 화면을 창 안에 **정수 배율**로 키워 가운데 (Aspect keep, 남는 곳 검정) — `Boot.gd` 가 창 크기가 바뀔 때마다 계산 |
| Stretch | Mode = `disabled` (7단계에서 `viewport` → 바꿈, 아래 참고) |
| 텍스처 필터 | Nearest (프로젝트 기본 + SubViewport + 컨테이너) |
| 물리 틱 | 60, 렌더 프레임당 최대 1틱 (`max_physics_steps_per_frame = 1`, 아래 참고) |
| 픽셀 스냅 | 2D Transform / Vertex 모두 켬 |
| 렌더러 | Compatibility (2D 픽셀 게임에 충분, 저사양·웹 대응) |
| 배경색 | `#05060d` |

입력 맵 (Project Settings → Input Map 에서 바꿀 수 있음)

|---|---|
| `move_left` / `move_right` | A / D (←/→) |
| `jump` | Space |

- `Config.gd` 이름 규칙: 프로토타입에서 대문자였던 이름(`AIM_TIME` 등)은 그대로, camelCase 는 snake_case (`runSpeed` → `run_speed`).
- 방은 `Room.tscn` 의 `Terrain` 레이어에 에디터에서 직접 칠해서 고칠 수 있다. 타일 8px, 테스트 방 120 × 34 칸.
  웹 프로토타입 좌표를 8px 격자에 맞추느라 바닥 윗면은 238 → 240, 발판 A/C 는 190/188 → 192, B 는 146 → 144 로 몇 px 옮겼다
  (점프 최대 높이 55px 안에 모두 닿음).

### 3단계 확인
| 항목 | 결과 | 프로토타입 |
|---|---|---|
| 히트스톱 `hitstop(6)` | 정확히 6틱 월드 정지 후 time_scale 1.0 복귀 (언제 호출해도) | 같음 |
| 근접 적 | 추적 → 예고 25틱(0.4초) → 공격 → 플레이어 즉사 | 같음 |
| 플레이어 사망 | 사망음 + 히트스톱 4틱(0.06초) + "R — 재시작" | 같음 |
| 직접 베기 | 예고 시작 직후 베면 적 즉사 (휘두르기음 + 처치음) | 같음 |
| 근접 패링 | 예고 마지막 0.1초 안에 베면 패링음 + 히트스톱 6틱 + 적 즉사, 플레이어 생존 | 같음 |
| 히트스톱 중 클릭 | 멈춘 동안엔 안 베고, 풀리자마자 베기 | 같음 |
| 두 명 처치 | CLEAR + 클리어음 | 같음 |
| 효과음 | `time_return.wav` 길이 0.935초 읽음, `slowmo_loop` 반복 재생 설정, 합성음 휘두르기 0.16초·사망 0.4초·클리어 0.49초 | 같음 |

- **시간 처리**: 히트스톱·슬로우는 `Engine.time_scale`. time_scale 이 0 이어도 물리 틱은 실제 시간으로 계속 오고 delta 만 0
  (Godot 4.5.1 에서 확인) → 이때 게임 노드는 `TimeManager.frozen` 을 보고 입력만 모아 둔다. 실제 시간 연출은 `TimeManager.real_frames`.
- **효과음**: Godot 오디오는 time_scale 영향을 받지 않아 슬로우·히트스톱 중에도 실제 시간으로 재생. 페이드는 `Tween.set_ignore_time_scale`.
- `slowmo_loop.wav` 는 임포트 설정에서 Loop Mode = Forward.

| 항목 | 결과 | 프로토타입 |
|---|---|---|
| 조준 → 발사 | 조준 시작 후 39틱째 고정(0.65초), 48틱째 발사(0.8초), 총소리 | 같음 |

| 타이밍 판정 창 | 베기 시작 − 발사 = −117ms 사망 · −100ms 패링 · 0ms 패링 · +50ms 패링 · +67ms 사망 | 같음 (−100 ~ +50ms) |
| 안 베면 | 발사 후 4틱째 사망 (PARRY_LATE 0.05초가 지난 첫 틱) | 같음 |
| 사격 패링 | 패링음 + 히트스톱 6틱 + 반사탄(3px 노랑)이 쏜 적 처치 + 처치음 + 원이 노랗게 퍼짐 | 같음 (슬로우 시퀀스는 5단계) |
| 고정 후 피함 | 발사됐지만 빗나감, 생존 | 같음 |
| 고정 전 움직임 | 조준선이 따라와 맞음 | 같음 |
| 엄폐물 뒤 | 상자 뒤에 있으면 조준 안 함(idle), 상자 위로 올라가면 조준 | 같음 |
| 두 총잡이 | 같은 틱에 조준을 시작시켜도 발사 간격 최소 0.317초 (≥ MIN_SHOT_GAP 0.3, 1틱 단위) | 같음 |
| 헛스윙 잠금 | 발사 0.27초 전 헛스윙 → 판정 창 안에서 다시 클릭해도 베기 막힘 → 사망 | 같음 |
| 화면 밖 총잡이 | 화면 가장자리에 축소 원(50%) + 총잡이 쪽 화살표 | 같음 |

- 사격 판정은 즉시 레이캐스트(`PhysicsRayQueryParameters2D`, 지형 비트만) + 플레이어·적은 사각형-선분 교차(Liang–Barsky).
- 탄이 플레이어에 닿으면 `pending_shots` 에 넣고 PARRY_LATE 동안 기다린다. 판정 시각은 `TimeManager.world_time`
  (슬로우 중에도 같은 비율). 플레이어 → 적 → Main 순으로 물리 틱이 돌아서(`process_physics_priority`) 같은 틱 안에서 판정이 끝난다.
- 반사 대상: 쏜 적이 마우스 방향 ±50° 안이면 최우선, 아니면 ±35° 안에서 가장 가까운 각도의 적 (거리 300, 벽에 가리면 제외).
- 다음에 쏠 총잡이의 원만 100%, 나머지는 50%.

| 9 | slowmo_loop 반복 시작, 노란 반사 궤적이 게임 시간에 맞춰 대상 쪽으로 뻗어감 | 같음 |
| 9 ~ 36 | 시간 속도 0.1 유지 | 같음 |
| 36 | time_return 재생, slowmo_in/loop 0.2초 동안 줄이며 정지 (48틱에 꺼짐) | 같음 |
| 36 ~ 92 | 시간 속도 0.1 → 1.0 (ease-in), 채도·비네트 복구, 줌 1.0 → 1.06 | 60틱 0.265 · 91틱 0.968 · 줌 최대 1.058 |
| 92 | time_return 이 끝나는 틱: 반사탄 명중 → 처치음 + 쏜 적 처치, 입력 잠금 해제 | 92틱 |
| 92 ~ 108 | 줌 16틱 동안 원상복구 | 20틱 뒤 1.0 |

| 항목 | 결과 |
|---|---|
| 패링 → 명중 사이 월드 시간 | 0.4318초 (프로토타입 계산값 0.4318) |
| 틱마다 시간 속도 | 기대값과 차이 < 0.000001 (렌더가 밀리지 않을 때) |
| 입력 잠금 | 시퀀스 중 클릭·이동 무시, 명중 다음 틱부터 다시 움직임 |
| 다른 총잡이 | 시퀀스 중엔 조준 고정 직전에서 기다리고, 끝난 뒤 발사 |
| 시퀀스 중 사망/재시작 | 시퀀스 취소, time_scale 1.0, 슬로우 소리 정리 |
| 근접 패링 | 같은 패링 연출 (섬광 1프레임 · 링 2겹 · 흔들림 10px), 시퀀스 없이 바로 처치 |

- 시간 속도는 `Engine.time_scale` (= `TimeManager.set_slow`). 다음 틱부터 적용되므로 ParrySeq 가 틱 k 에 `scale_at(k + 1)` 을 넣는다.
  ParrySeq 는 TimeManager 다음, 플레이어·적보다 먼저 틱을 받아 명중이 그 틱의 월드 갱신 전에 일어난다.
- Godot 는 한 렌더 프레임에 물리 틱이 여러 번 돌면 그 틱들에 같은 time_scale 을 쓴다. 렌더가 60fps 아래로 밀리면
  속도 곡선이 한 틱 밀릴 수 있었다 → 7단계에서 렌더 프레임당 물리 1틱으로 제한해 해결 (7단계 확인 참고).
- 흔들림·줌은 카메라 `offset` / `zoom`. 흔들림 강도는 `Config.settings.shake` (7단계 옵션 메뉴).

- **Stretch 를 `viewport` → `disabled` 로 바꾼 이유**: 루트를 480×270 으로 렌더하면 확대된 화면의 한 줄(게임 픽셀 1/4)보다
  얇은 스캔라인을 그릴 수 없다. 그래서 게임은 480×270 SubViewport 에 그대로 렌더하고(최근접 필터·픽셀 스냅),
  `Boot.gd` 가 그것을 정수 배율로 키워 가운데 놓는다 — 보이는 결과는 `viewport` + `keep` + `integer` 와 같고,
  그 위에 창 해상도로 스캔라인을 그린다.
- **렌더 프레임당 물리 1틱**: Godot 는 한 렌더 프레임에 물리 틱이 여러 번 돌면 그 틱들에 같은 `time_scale` 을 쓴다
  (프레임 시작 때 한 번 읽음). 히트스톱·패링 시퀀스의 틱 단위 속도 곡선이 어긋나지 않게 프레임당 1틱으로 제한했다.
  화면이 60fps 아래로 떨어지면 따라잡지 않고 그만큼 게임이 느려진다 (판정은 월드 시간이라 일관됨).
- 일시정지(옵션 메뉴 · F4)는 `SceneTree.paused`. 방·플레이어·연출 노드는 PAUSABLE, Main(흔들림 미리보기·입력)·HUD·메뉴는 ALWAYS.
