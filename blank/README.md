# 공백 (BLANK) — Godot 4

웹 프로토타입(`../parry/`)으로 검증한 패링 특화 원히트 액션을 Godot 4.x(GDScript)로 다시 만드는 프로젝트. 시우 공방.

## 열기 / 실행
1. Godot **4.5 이상** (TileMapLayer 사용 → 최소 4.3, 4.5.1 에서 확인)으로 `blank/project.godot` 를 연다.
2. 처음 열면 에디터가 `art/`, `sounds/` 를 자동으로 임포트한다 (`.godot/` 캐시는 git 에 넣지 않음).
3. F5 (프로젝트 실행) → `scenes/Boot.tscn` ("시우 공방" 로고 2초 → 게임). `Main.tscn` 만 따로 실행(F6)해도 된다 (로고·스캔라인 없이 창 크기 그대로).

## 프로젝트 설정 (project.godot)
| 항목 | 값 |
|---|---|
| 게임 화면 | 480 × 270 (`Boot.tscn` 의 SubViewport) |
| 창 크기 | 1920 × 1080 (window override) |
| 확대 | 게임 화면을 창 안에 **정수 배율**로 키워 가운데 (Aspect keep, 남는 곳 검정) — `Boot.gd` 가 창 크기가 바뀔 때마다 계산 |
| Stretch | Mode = `disabled` (7단계에서 `viewport` → 바꿈, 아래 참고) |
| 텍스처 필터 | Nearest (프로젝트 기본 + SubViewport + 컨테이너) |
| 물리 틱 | 60, 렌더 프레임당 최대 1틱 (`max_physics_steps_per_frame = 1`, 아래 참고) |
| 픽셀 스냅 | 2D Transform / Vertex 모두 켬 |
| 렌더러 | Compatibility (2D 픽셀 게임에 충분, 저사양·웹 대응) |
| 배경색 | `#05060d` |

입력 맵 (Project Settings → Input Map 에서 바꿀 수 있음)

| 액션 | 키 |
|---|---|
| `move_left` / `move_right` | A / D (←/→) |
| `jump` | Space |
| `slash` | 마우스 왼쪽 |
| `restart` | R |
| `mute` | M |
| `menu` | ESC (일시정지 메뉴) |

디버그 키 (`Debug.gd`): F1 반사 보정 표시 · F2 타격감 토글 패널 · F3 슬로우 10% · F4 프레임 진행 (F4 한 틱, Enter 해제) · F5 패링 타이밍 바 + 입력 오차 ms
· F6 다음 방으로 바로 (보스방에서는 무대 페이즈 상태 순환) · F7 지금 방 즉시 클리어 · F8 철견 즉시 휘청 · F9 철견 포즈 뷰어 (숫자 키, Shift+숫자)
· F10 철견 패턴 강제 (① ~ ⑤) · F11 철견 페이즈 순환 1 → 2 → 3 → 피날레 (Shift+F11 = 다음 페이즈 전환 연출 · 페이즈 3 이면 피날레)
· F11 (보스방 밖) 처음 만나는 적 소개 기록 초기화 · 디버그 모드 왼쪽 위 = 이 방 사망 수 + 최근 원인 3개 (어떤 적의 어떤 공격 · 종류 · 패링 오차)
(F6 ~ F11, 왼쪽 아래 "1장 - 방 3/6" 표시는 디버그 빌드에서만 — 에디터 실행 · 디버그 내보내기)

- 근접 패링 판정 창(`in_parry_window`)·칼 판정(`slash_hits`, `slash_hits_rect`)은 3단계 근접 적이 사용.

### 3단계 확인
| 항목 | 결과 | 프로토타입 |
|---|---|---|
| 히트스톱 `hitstop(6)` | 정확히 6틱 월드 정지 후 time_scale 1.0 복귀 (언제 호출해도) | 같음 |
| 근접 적 | 추적 → 예고 25틱(0.4초) → 공격 → 플레이어 즉사 | 같음 |
| 플레이어 사망 | 사망음 + 히트스톱 4틱(0.06초) + "R — 재시작" | 같음 |
| 직접 베기 | 예고 시작 직후 베면 적 즉사 (휘두르기음 + 처치음) | 같음 |
| 근접 패링 | 예고 마지막 0.1초 안에 베면 패링음 + 히트스톱 6틱 + 적 즉사, 플레이어 생존 | 같음 |
| 히트스톱 중 클릭 | 멈춘 동안엔 안 베고, 풀리자마자 베기 | 같음 |
| 두 명 처치 | CLEAR + 클리어음 | 같음 |
| 효과음 | `time_return.wav` 길이 0.935초 읽음, `slowmo_loop` 반복 재생 설정, 합성음 휘두르기 0.16초·사망 0.4초·클리어 0.49초 | 같음 |

- **시간 처리**: 히트스톱·슬로우는 `Engine.time_scale`. time_scale 이 0 이어도 물리 틱은 실제 시간으로 계속 오고 delta 만 0
  (Godot 4.5.1 에서 확인) → 이때 게임 노드는 `TimeManager.frozen` 을 보고 입력만 모아 둔다. 실제 시간 연출은 `TimeManager.real_frames`.
- **효과음**: Godot 오디오는 time_scale 영향을 받지 않아 슬로우·히트스톱 중에도 실제 시간으로 재생. 페이드는 `Tween.set_ignore_time_scale`.
- `slowmo_loop.wav` 는 임포트 설정에서 Loop Mode = Forward.

## 출구 문 — 하운드 보안 셔터
방 안의 하운드 경비원이 전부 쓰러지면 보안 잠금이 풀려 열린다. 이미지 없이 `Door._draw` 로 그리고, 수치는 모두 `Config.door`.
출구 표시(상태등 · 간판 · 빛 번짐 · 화면 밖 화살표 · 무전 글자)는 하늘색만 — 빨강 · 노랑 · 보라는 쓰지 않음.

**종류** — 방 씬에서 `Exit` / `Entrance` 노드의 `door_type` 으로 고름 (같은 상태 규칙, 모양만 다름)

| door_type | 생김새 | 들어가는 법 | 노드 위치 |
|---|---|---|---|
| `shutter` | 문틀 24×40 (금속 테두리 2px) · 2px 간격 가로줄 셔터(짙은 남색 + 회색) · 가운데 하운드 마크(삼각형) · 문 위 4×2 상태등 + 네온 `>>>` | 셔터가 올라간 문 안쪽으로 걸어 들어감 | 문 아래 가운데 |
| `vent` | 벽·천장 철망 덮개 20×14 | 덮개가 떨어져 나간 구멍으로 점프 | 덮개 가운데 |
| `manhole` | 바닥 맨홀 (구멍 16px, 덮개 20px) · 간판 `vvv` | 덮개가 옆으로 밀려난 구멍으로 떨어짐 | 바닥 윗면 가운데 (8px 격자에 맞춰짐, 아래 지형은 자동으로 뚫림) |
| `boss` | 셔터의 1.5배 (36×60) · 두꺼운 이중 셔터 · 잠금 빗장 · 회전 상태등 | 이중 셔터가 위아래로 갈라진 뒤 걸어 들어감 | 문 아래 가운데 |

문이 놓인 자리의 지형 타일은 실행할 때 지워져서, 벽 속에 문을 놓아도 통로가 생긴다.

**상태**
| | 잠김 (적이 남음) | 열리는 중 | 열림 |
|---|---|---|---|
| 충돌 | 있음 (플레이어 · 적 · 총알 · 시야를 막음) | 있음 (완전히 열릴 때까지 통과 불가) | 없음 |
| 상태등 | 회색, 2초마다 0.12초 희미하게 깜빡 | 하늘색 (보스: 회전하며 켜짐) | 하늘색 |
| 간판 | 꺼짐 | 3번 지지직 깜빡인 뒤 0.38초부터 켜짐 | `>>>` 가 오른쪽으로 흐름 |
| 그 밖 | | 시간표 (아래) | 안쪽은 검은 통로, 문 앞 바닥에 하늘색 빛 번짐(반투명 타원), 빛 속을 지나는 빗방울이 바닥에 닿으며 반짝 |

**시간표** (실제 시간, 효과음 속 소리와 맞춤 — 마지막 적의 16프레임 킬 연출이 끝난 바로 다음 틱에 시작)
- shutter · vent · manhole: `door_open.wav`(0.9초, 볼륨 0.7) → **0.50초 2프레임 멈칫**(첫 "덜컹") → **0.64초 완전히 열림**(두 번째 "덜컹") + 먼지 + 화면 흔들림 2px.
  철망은 0.50초까지 덜덜 떨리다 처지고 0.64초에 떨어져 나가 바닥에 구른 뒤 사라짐. 맨홀 덮개는 같은 곡선으로 옆으로 밀려남
- boss: `door_boss.wav`(3.5초, 볼륨 0.9) → 0.35초 잠금 해제 "쿵"(빗장 풀림, 흔들림 3px) → 0.4~2.1초 문 틈새 증기 + 미세 진동 1px →
  **2.18초 이중 셔터가 0.2초 만에 위아래로 갈라짐** + 흔들림 6px → 2.38초 통과 가능.
  열리는 동안(+ 열린 뒤 1.5초) 화면 아래에 잡음 섞인 무전 한 줄 — 문 노드의 `radio_text` 로 입력 (글자가 한 자씩, 잡음 글자 · 지직 줄)
- 출구가 열렸는데 화면 밖이면 화면 가장자리에 하늘색 작은 화살표 (화면 안에 들어오면 사라짐)
- `sounds/door_open.wav` · `door_boss.wav` 가 없으면 무음

## 보스 "철견" 재제작 — 0단계: 효과음 등록
보스 효과음 2차 9종을 `sounds/` 에 넣고 `Audio` 에 등록 (앞 무음 제거 · 음량 정리된 파일 그대로).

| 파일 | 길이 | 가장 큰 소리 | 볼륨 (`Config.audio`) | 용도 |
|---|---|---|---|---|
| gun_cock | 0.25s | 0.07s | SFX_GUN_COCK 0.8 | 슬라이드 사격 예고 |
| quickdraw | 0.35s | 0.22s | SFX_QUICKDRAW 0.9 | 속사 권총 뽑기 |
| pistol_whip | 0.45s | 0.12s | SFX_WHIP 0.9 | 건카타 내려치기 |
| execute | 0.65s | 0 | SFX_EXECUTE 1.0 | 반격 베기 명중 |
| stagger | 0.50s | 0 | SFX_STAGGER 0.8 | 철견 휘청 |
| explosion | 0.60s | 0 | SFX_EXPLOSION 1.0 | 물탱크 폭발 |
| flashbang | 1.00s | 0 | SFX_FLASHBANG 0.9 | 조명 파괴 · 정전 |
| thunder | 0.90s | 0.17s | SFX_THUNDER 0.7 | 번개 |
| rain_loop | 4.00s | — | SFX_RAIN 0.35 | 보스방 빗소리 (이음새 없는 반복) |

- `Audio.play_synced(이름, 타격_월드시각)`: 피크 위치(`Audio.PEAKS`)만큼 일찍 재생해 그 지점이 타격 순간에 오게.
  소리는 실제 시간으로 재생되므로 남은 월드 시간을 지금 시간 속도로 나눠 비교 — 슬로우면 그만큼 늦게 시작, 히트스톱 중엔 기다림,
  이미 늦었으면 앞부분을 건너뛰고 재생. `cancel_synced` 로 취소
- `Audio.play_loop` / `set_loop_volume` / `stop_loop`: 반복 재생 (풀과 따로, 실제 시간 페이드). `stop_all`(재시작)이면 같이 멈춤
- 효과음은 시간 속도(슬로우 · 히트스톱)의 영향을 받지 않음 (Godot 오디오는 `Engine.time_scale` 과 무관)
- 아직 없는 dash_whoosh · slide · jump 는 넣으면 바로 쓰이고 없으면 무음 (볼륨 키 SFX_DASH · SFX_SLIDE · SFX_JUMP 0.8)

**들어 보기** — F2 패널: **B** 새 효과음 차례로 재생 (rain_loop 차례에서는 빗소리 반복 켜기/끄기),
**N** 싱크 테스트 — 0.6초 뒤 한 순간에 맞춰 quickdraw + gun_fire / pistol_whip + parry_chang (번갈아)

**확인** (Godot 4.5.1 자동 테스트, 실제 시간 기준)
| 경우 | 시작 | 피크 | 목표 |
|---|---|---|---|
| quickdraw, 0.5초 뒤 | 0.283 | 0.497 | 0.500 |
| pistol_whip, 0.5초 뒤 | 0.383 | 0.497 | 0.500 |
| quickdraw, 슬로우 50% (월드 0.5 = 실제 1.0) | 0.783 | 0.997 | 1.000 |
| quickdraw, 0.1초 뒤 (이미 늦음 → 0.12초 건너뜀) | 0.000 | 0.097 | 0.100 |
| quickdraw, 히트스톱 20틱 중 예약 | 0.417 | 0.631 | 0.633 |
| rain_loop | 반복 구간 = 파일 전체 (192000 샘플), 4.7초 뒤에도 재생 중, 볼륨 0.35 → 0.6 | | |

## 보스 "철견" 재제작 — 1단계: 몸체 + 이동 + 반격 시스템
예전 철견 (자세 게이지 · 그로기 · 처형 · 패턴 7종 · 수류탄 · 섬광 화면)은 전부 지우고 새로 만듦. 수치는 모두 `scripts/boss/CheolgyeonConfig.gd`.
1단계에는 아직 공격 패턴이 없다 (2단계) — 철견은 이동 데모 루프로 움직이고, F8 로 휘청을 걸어 반격 베기를 시험한다.

**몸체 (전투 로직과 분리)** — `scenes/CheolgyeonBody.tscn`
- 키 약 56px: 어깨 넓은 역삼각형 몸, 넓은 챙 페도라, 다리 뒤로 늘어진 긴 코트 자락, 양손 권총. 짙은 남색 ~ 검정 + 옅은 파란 림라이트 1px
  (부위를 CanvasGroup 으로 한 장으로 합친 뒤 `rim_outline` 셰이더로 바깥 테두리만 — 휘청 중엔 테두리가 흰색으로 깜빡임)
- 뼈대 `Rig / Hip ─ Coat · ThighB─ShinB · ThighF─ShinF · Torso ─ ArmB─GunB · Head(+Hat) · ArmF─GunF`, 뼈마다 Polygon2D 하나.
  스프라이트로 바꿀 때는 각 뼈의 Polygon2D 를 Sprite2D 로 갈아 끼우면 됨 — 로직은 `pose · snap · ghost · facing · muzzle · silhouette · set_flash` 만 씀
- 포즈 17개 = AnimationPlayer 애니메이션 (키프레임 하나씩): idle · dash · slide · whip_windup · whip_smash · kick_ready · kick · jump · air_fire ·
  land · duel · draw_fire · aim_up · stagger · roar + 보조 crouch (대시 · 점프 전 웅크림) · block (칼 막기). 에디터에서 키프레임을 직접 고쳐도 됨
- **키포즈 전환** (`snap`): 예고 정지 → 1프레임에 다음 포즈로 + 이전 포즈 잔상 (0.16초) + 이전 · 다음 포즈를 잇는 스미어 (1틱) → 여운 정지.
  공용 시스템에 이런 전환이 따로 없어서 몸체 안에 만듦 (플레이어 잔상과 같은 방식). 이동 포즈끼리는 0.06초 블렌드

**이동 (걷기 없음)**
- 대시: 0.15초 웅크림(crouch) + 발밑 먼지 → 450px/초 순간 돌진, 0.04초마다 잔상 → 0.06초에 멈춤
- 슬라이드: 250px/초로 바닥을 미끄러짐, 0.03초마다 먼지
- 점프: 0.1초 웅크림 → 0.38초 포물선 (발판 BossPerches 로, 또는 바닥으로) → 착지 웅크림(land) 0.12초 + 먼지
- 이동 하나는 0.4초 안 (`MOVE_MAX`) — 더 멀면 거기까지만
- 1단계 데모 루프: 멀면 다가가는 대시 / 가까우면 물러나는 대시 → 플레이어를 지나치는 슬라이드 → 발판으로 점프 → 바닥으로 점프 → … (사이 0.3초)

**휘청 → 반격 베기**
- 휘청 0.7초 (`STAGGER_TIME`): stagger 포즈 (키포즈 전환), 흰 테두리 깜빡임, stagger.wav, 체력 칸 마지막 칸도 깜빡임
- 휘청 중 베기 → 철견이 120px 안이면 0.08초 동안 철견에게 자동 돌진하며 벰 (`COUNTER_LUNGE_RANGE` · `COUNTER_LUNGE_TIME`, 15px 앞에서 멈춤)
- 명중: execute.wav + 히트스톱 8프레임 + 흰 섬광 1프레임 + 흔들림 6px + 코트 조각 파편 7개 + 철견 30px 넉백 → 체력 -1.
  컷인 · 긴 슬로우 없음. 넉백이 끝나면 바로 다음 이동. 휘청을 놓치면 0.3초 뒤 다음 이동
- 반사탄이 철견에 맞으면 휘청 (2단계 속사 · 슬라이드 사격 마지막 탄에서 씀)
- 체력 9 — 화면 위 하늘색 칸 9개. 0 이 되면 지금은 일반 16프레임 킬 연출 → 무전 → 출구 (4단계에서 피날레로 바뀜)
- 휘청이 아닐 때 베면: 권총으로 막음 (block 포즈) — boss_armor.wav (피치 1.15) + 총에서 불꽃, 피해 없음, 플레이어 0.2초 경직 + 살짝 밀려남

**패링 (이 보스전)**
- 일반 패링 (콤보 중간 공격) `Main.boss_parry_fx`: parry_chang + 히트스톱 5프레임 + 노란 불꽃 + 실제 0.1초 동안 시간 50% (`TimeManager.slow_for`) — 2단계 패턴이 씀
- 풀 패링 슬로우 시퀀스는 이 보스전에서 페이즈 전환 · 피날레에만 (3·4단계). 패링 성공 직후 헛스윙 쿨타임 없음 (기존 규칙)

**배경음** — 방에 `ambience` 를 정할 수 있음 (`Room.ambience`, 보스방 = rain_loop, 볼륨 0.35). 재시작해도 끊기지 않고, 배경음 없는 방으로 가면 멈춤

**디버그** — F8 철견 즉시 휘청 · F9 포즈 뷰어 (철견이 멈추고, 숫자 키 1 ~ 0 / Shift+1 ~ 7 로 그 포즈로 키포즈 전환, 같은 키 = 다시 전환)

**확인** (Godot 4.5.1 자동 테스트 + 4.7 에디터 새 캐시로 열기)

## 보스 "철견" 재제작 — 2단계: 패턴 3종 + 페이즈 1 루프
수치는 `CheolgyeonConfig.gd`. 이 보스전의 사격 패링은 모두 **일반 패링** (parry_chang + 히트스톱 5 + 노란 불꽃 + 0.1초 50%) —
콤보 마지막 공격만 패링하면 **즉시 휘청** (0.7초, 반격 베기 기회). 긴 슬로우는 쓰지 않음.

## 철견 수정 — 1단계: 플레이어 구르기 (모든 스테이지 공통)
수치는 `Config.roll`. 입력 `roll` (기본 Shift) — project.godot 의 입력 맵, 그리고 ESC 옵션 메뉴 "구르기 키" 에서
Enter (또는 클릭) → 바꿀 키를 누르면 바뀜 (ESC 취소, 지금은 옵션 화면 "조작", user://settings.json).

- 이동 방향으로 (입력이 없으면 바라보는 방향) 64px · 0.30초, 시작부터 0.25초 무적 (`ROLL_DISTANCE` · `ROLL_TIME` · `ROLL_IFRAME`)
- 쿨타임 0.40초 (구르기가 끝난 뒤부터), 공중에서는 불가, 경직 · 입력 잠금 중 불가
- 무적 중: 히트스캔 탄이 몸을 통과 (조준선 끝까지 날아감), 근접 공격 · 충격파 · 보라색 공격 모두 통과.
  쏘는 순간엔 맞았지만 아직 판정 중(늦은 판정 창)인 탄도 그때 무적이면 피함
- 적 · 철견의 몸은 원래 부딪히지 않아 뚫고 지나감 (떨어진 네온 간판 같은 무대 장애물은 막힘)
- 구르기 중 베기(패링) 입력은 무시, 베던 중에 구르면 베기가 끊김. 구르기가 끝나는 즉시 베기 가능
- 연출: 몸을 둥글게 말아 한 바퀴 회전, 0.04초마다 잔상, 0.05초마다 바닥 먼지
- 효과음: roll.wav (볼륨 0.6) → 없으면 dash_whoosh 피치 1.3 → 그것도 없으면 무음. 지금은 둘 다 없어서 무음
- 조작 안내 줄에 "Shift 구르기" 추가

**확인** (Godot 4.5.1 자동 테스트)
| 항목 | 결과 |
|---|---|
| 거리 · 시간 · 무적 | 64px · 18틱(0.30초) · 무적 15틱(0.25초), 왼쪽(A)으로도 -64px |
| 쿨타임 | 끝난 뒤 0.40초 — 바로 다시 누르면 안 구름, 0.43초 뒤엔 구름 |
| 공중 | 점프 중 Shift → 안 구름 |
| 베기 | 구르는 중 클릭 → 안 벰, 끝난 바로 다음 틱 클릭 → 벰 |
| 총잡이 탄 | 발사 0.08초 전 구르기 → 생존 · 발사 직후(판정 중) 구르기 → 생존 · 안 구르면 사망 |
| 철견 | 건카타 1타에 구르기 → 생존 + 철견 몸을 뚫고 반대편으로 · ③ 충격파에 구르기 → 생존 |
| 효과음 | dash_whoosh 가 있으면 피치 1.3 으로 재생 |
| 키 바꾸기 | 메뉴에서 Ctrl 로 → Ctrl 로 구르고 Shift 로는 안 구름 |

## 철견 수정 — 2단계: 공격 종류 (NORMAL · OPPORTUNITY · EVADE)
수치는 `Config.attack` (상수 `Config.ATK_NORMAL` · `ATK_OPPORTUNITY` · `ATK_EVADE`). 모든 적 공격에 `attack_type` 이 붙음
(총잡이 `next_type` · 근접 적 `attack_type` · 철견 탄 `type` · 건카타 `_whip.types` · 충격파 `type`, 발사 원 정보 · 판정 대기 탄에도).

| 종류 | 표시 | 대응 |
|---|---|---|
| NORMAL | 빨간 줄어드는 원 **1겹** · 빨간 점멸 (기존) | 구르기로 피하거나 패링. 철견: parry_chang + 히트스톱 4프레임 + 노란 불꽃, 피해 · 휘청 없음 (슬로우 없음) |
| OPPORTUNITY | 빨간 원 **2겹** (바깥 원 +4px · 2px 두께 · 흰색 쪽으로 35% 밝게 · 최소 투명도 60%) + 공격 0.15초 전 '칭' (boss_armor 피치 1.8 · 볼륨 0.4) + 원 중심 4갈래 반짝임 | 패링해야만 철견 휘청 (히트스톱 5 + 짧은 슬로우는 그대로). 피해도 되지만 기회를 놓침 |
| EVADE | 보라 (기존 발차기 · 충격파 · 보라 탄) | 패링 불가 — 구르기 무적이나 점프로만 |

지금 붙어 있는 종류 (3단계에서 패턴별로 다시 배치):
- 일반 총잡이 · 근접 적: NORMAL (보라 확률 `unparryable_chance` 이면 EVADE). **패링 결과는 그대로** — 총잡이는 반사탄 슬로우로 처치, 근접 적은 패링 처치
- 철견 탄: 휘청을 주던 탄 (① 마지막 탄 · ④ 속사 · ⑤ 두 번째 도탄) 과 오프닝 · 피날레 결투 탄 = OPPORTUNITY, 나머지 NORMAL
- 철견 건카타: 1 · 2타 NORMAL, 발차기 EVADE, 휘청을 주는 3타 = OPPORTUNITY → 근접 타격에도 내려칠 권총 둘레에 2겹 원 (감기 시작 → 타격, 0.5초)
- 착지 충격파: EVADE

**연습 방** — 디버그 빌드에서 **Shift+F12** (다시 Shift+F12 = 원래 방으로 · 피날레 작업 뒤 F12 에서 옮김). `rooms/test/room_attack_types.tscn`
- 더미 (`EnemyDummy`, 수치 `Config.dummy`): 제자리에서 NORMAL → OPPORTUNITY → EVADE 를 번갈아 쏨 (조준 0.8초 · 간격 1.2초), 죽지 않음
- NORMAL 패링 = 철견과 같은 일반 패링 연출만 · OPPORTUNITY 패링 = 반사탄이 맞고 1초 휘청 (흰 테두리 깜빡임) → 그동안 베면 반격 명중 (가까우면 자동 돌진) · 휘청 아닐 때 베면 "막힘"
- 왼쪽 위 안내판: 실제 원 세 종류 (1겹 · 2겹 · 보라) 가 나란히 줄었다 커졌다 함

**확인** (Godot 4.5.1 자동 테스트 + 4.7 에디터 새 캐시로 열기)
| 항목 | 결과 |
|---|---|
| 더미 순서 | normal → opportunity → evade |
| 칭 | 발사 0.150초 전, boss_armor 피치 1.8 |
| 더미 NORMAL 패링 | 히트스톱 4틱, 슬로우 없음, 더미 그대로 (휘청 없음) |
| 더미 OPPORTUNITY 패링 | 히트스톱 5틱 → 휘청 → 베기 = 반격 1회 |
| EVADE | 원 정보 parryable = false · 구르기 → 생존 · 패링 시도 → 사망 |
| 철견 ① | 탄 종류 normal, normal, opportunity · 첫 탄 패링 = 히트스톱 4, 체력 9 그대로, 슬라이드 계속 |
| 철견 ② | 타격 종류 normal, normal, opportunity · 3타 2겹 원 (0.5초) |
| 일반 총잡이 | normal, 패링 → 반사탄으로 처치 (기존 그대로) |
| 회귀 | 방 1 ~ 5, 총잡이 패링, 1단계 구르기 테스트 모두 통과 |

## 철견 수정 — 3단계: 패턴별 공격 종류 재배정
"대부분은 피하고, 기회 공격만 받아친다". 수치는 `CheolgyeonConfig.gd`.

| 패턴 | 공격 종류 | 바뀐 점 |
|---|---|---|
| ① 슬라이드 사격 = 피하는 패턴 | 모든 탄 NORMAL (1겹) | 마지막 탄 휘청 없앰 — 패링해도 피해 · 휘청 없음. 끝나면 플레이어 뒤쪽에서 플레이어를 보고 0.4초 정지 → 곧바로 다음 패턴 (`SLIDE_SHOT_RECOVER`, 이 정지가 패턴 사이 공백 대신). 탄 간격 0.30 → **0.42초** (아래) |
| ② 돌진 건카타 = 기회 패턴 | 1 · 2타 NORMAL, 3타 OPPORTUNITY (2겹 원), 발차기 EVADE | 그대로 (2단계에서 이미 배정) |
| ③ 점프 사격 = 빈틈 패턴 | 공중 2발 NORMAL, 착지 충격파 EVADE | 착지 경직 0.5 → **0.7초** "빈틈": 흰 테두리 깜빡임 + 머리 위 "빈틈" 글자, 베면 반격 베기 (휘청과 같은 피해) |
| ④ 속사 = 기회 패턴 | 진짜 탄 OPPORTUNITY, 가짜 움찔 헛스윙 뒤 즉시 사격 NORMAL | 헛스윙 직후에도 구를 수 있게 (아래) |
| ⑤ 도탄 사격 = 기회 패턴 | 1번째 NORMAL, 2번째 OPPORTUNITY + 방향 패링 | 그대로 (두 탄 모두 튕긴 쪽으로 베어야 하는 방향 패링) |

**구르기 보정** (`Config.roll`)
- `ROLL_BUFFER` 0.1초: 베기 돌진 중 · 히트스톱 중에 누른 구르기를 0.1초 동안 기억
- `ROLL_GROUND_SNAP` 4px: 베기 돌진으로 바닥에서 살짝 뜬 순간도 바닥으로 침 (점프 중엔 여전히 불가).
  이게 없으면 가짜 움찔에 헛스윙한 뒤 0.12초 즉시 사격을 구르기로 피할 수 없었음

**① 탄 간격 0.42초** — 구르기는 0.30초 동안 끝날 때까지 점프 · 베기가 안 되고 무적은 0.25초라, 간격 0.30초에선
한 발을 구르면 다음 발이 반드시 맞음. 4단계 NORMAL 값(0.42)을 먼저 적용 → 굴러 한 발 피하고 다음 발은 점프 · 패링 가능

**확인** (Godot 4.5.1 자동 테스트 + 4.7 에디터 새 캐시로 열기)
| 항목 | 결과 |
|---|---|
| ① | 종류 normal ×3 · 마지막 탄 패링 → 생존, 체력 9, 휘청 없음 · 끝난 위치 = 플레이어 반대편 · 정지 0.42초 → 바로 ② 시작 |
| ① 피하기만 | 패링 없이 구르기 2번 + 점프 1번으로 생존 (철견 쪽으로 구르면 몸을 뚫고 지나감) |
| ② | 종류 normal, normal, opportunity · 1 · 2타 패링 → 콤보 계속, 3타 패링 → 휘청 |
| ③ | 공중 normal ×2 · 충격파 evade ×2 · 빈틈 0.70초 (land 포즈) · 빈틈에 베기 → 체력 6 → 5 |
| ④ | 진짜 탄 opportunity · 헛스윙 즉시 사격 normal → 구르기로 생존 |
| ⑤ | 종류 normal, opportunity |
| 회귀 | 방 1 ~ 5, 총잡이 패링, 1단계 구르기 테스트 모두 통과 |

## 철견 수정 — 4단계: 난이도 프리셋 + 체력 조정
옵션 화면 "게임" **난이도** (← → 로 EASY · NORMAL · HARD, Enter · 클릭 = 차례로). 기본 NORMAL, user://settings.json 에 저장.
표는 `Config.difficulty_presets`, 지금 값은 `Config.diff` (`Config.set_difficulty`). 표에 있는 철견 상수는 `CheolgyeonConfig.gd` 에서 빼고
"→ 난이도 프리셋" 주석만 남김. HARD = 그동안 쓰던 값과 거의 같음.

| 항목 | EASY | NORMAL | HARD | 적용 |
|---|---|---|---|---|
| PARRY_EARLY / LATE | 0.18 / 0.10 | 0.14 / 0.08 | 0.10 / 0.05 | `Config.shot` 에 써 넣음 — 모든 적 사격 패링 + 원의 판정 띠 |
| TELEGRAPH_TIME | 0.40 | 0.30 | 0.18 | 철견 공격 직전 웅크림 예고: ① 슬라이드 · ② 돌진 · ③ 점프 (자리 잡는 대시는 그대로 0.15) |
| SLIDE_SHOT_INTERVAL | 0.50 | 0.42 | 0.30 | ① 탄 간격 |
| WHIP_INTERVAL | 0.45 | 0.35 | 0.25 | ② 1타 → 2타 |
| QUICKDRAW_RING_TIME | 0.55 | 0.45 | 0.30 | ④ 원 = 움찔 → 발사 (오프닝 · 피날레 결투도) |
| FAKE_TWITCH_CHANCE (P2/P3) | .15/.25 | .25/.40 | .50/.60 | ④ 가짜 움찔 확률 |
| DIRECTIONAL_PARRY_ANGLE | 90 | 80 | 60 | ⑤ 방향 패링 ± 각도 |
| SHOCKWAVE_SPEED | 180 | 220 | 300 | ③ 충격파 |
| STAGGER_TIME | 1.3 | 1.0 | 0.7 | 휘청 (연습 더미도) |
| COUNTER_LUNGE_RANGE | 200 | 170 | 120 | 반격 베기 자동 돌진 |
| BOSS_HP / 전환 체력 | 6 / 4,2 | 6 / 4,2 | 9 / 6,3 | 체력 칸 수 = BOSS_HP. 페이즈 전환 · 체크포인트 체력도 프리셋 (`phase_hp`) |
| PATTERN_GAP (P1/P2/P3) | .9/.7/.6 | .7/.55/.45 | .4/.3/.2 | 패턴 사이 공백 |
| 페이즈 3 이어 붙이기 | 끔 | 끔 | 켬 | |

- 난이도를 바꾸면 바로 적용, **보스 체력 칸 · 전환 체력만 방을 다시 시작할 때부터** (싸우는 중에 칸 수가 바뀌지 않게)
- 패턴 사이 공백: 자리 잡는 대시가 필요하면 대시 뒤 남은 공백만큼 기다림 (`repo_wait`) — 그동안은 대시가 공백을 대신해 EASY 의 0.9초가 줄어들었음.
  ① 슬라이드 사격 뒤 0.4초 정지는 3단계대로 공백 대신
- 디버그 타이밍 줄의 "공백" 은 지금 난이도 공백 + 0.05초를 넘으면 빨강

## 철견 수정 — 5단계: 오프닝 · 피날레 소폭 수정 + 사망 기록
수치는 `CheolgyeonConfig.gd` (`OPEN_DODGE_*`).

**오프닝 속사** — 탄은 OPPORTUNITY (2겹 원 + 칭)

## 대사 넘김 속도 늦춤
글자가 하나씩 나오는 속도는 그대로, 다음 줄로 넘어가거나 사라지기까지의 시간만 대폭 늘림.
- 잡음 무전: 줄 사이 0.45 → 1.6초, 마지막 줄 뒤 사라질 때까지 2.5 → 4.5초 (`Config.ui_style.RADIO_LINE_GAP · RADIO_HOLD`)

- 철견 대사 표시 2.2 → 4초 (`LINE_TIME`). 오프닝 대사 3.8초 · 속사 시작 카드 뒤 3 → 4.7초, 구른 뒤 대사 → 페이즈 1 1.4 → 2.6초.
  피날레 대치 2.5 → 4초 (걸어가기 · 카메라는 그대로 2.5초, 남은 시간은 마주 선 채 대사), 쓰러질 때 대사 3초 → 끝난 뒤 무전 (여운 1.6초), 출구 문 여운 2 → 3.6초

  | room_enter | try (이 방 몇 번째 시도 — 사망 뒤 재시작 포함) |

  | parry_fail | 패링할 수 있는 공격 (NORMAL · OPPORTUNITY) 에 죽음 = 실패. type · enemy · attack · err_ms · err (+ 보스면 pattern · phase) |
  | parry_fail_update | 맞은 뒤 0.5초 안에 늦게 누름 → 바로 앞 실패의 err_ms (+늦음) |
  | roll | 구르기 한 번이 끝날 때: dodged (구르는 동안 맞았을 공격이 무적으로 통과했는가) · dodged_attack |
  | counter_success | target (철견 · 연습 더미) |
  | boss_phase | phase (opening · 1 · 2 · 3 · finale · defeated) — 도달 시각 = time 열 |
  | pause / resume | resume 에 paused_for (초) |
  | to_title | 일시정지 "타이틀로" |
  | option_change | key (difficulty · shake · approach · vol_* · fullscreen · bind_<동작>) · from · to · where (pause · title) |
  | chapter_clear | play_time · deaths · parries · counters · difficulty |
  | quit | reason (title_menu = 타이틀 "종료", window_closed = 창 닫기, exit = 그 밖의 종료) |

  - 체크포인트에서 다시 시작하자마자 사수에게 보이는가 → 없음 (보이는 사수는 모두 체크포인트 앞이라 다시 시작하면 사라짐)
  - 사수 (총잡이 · 연사병) 둘 이상이 동시에 보는 자리 (십자포화) → 5곳
  - 구간별 위협 점수 (근접 1 · 총잡이 1.5 · 척탄병 1.5 · 연사병 2 · 돌격병 2) ÷ 화면 수
- **고친 것** (`tools/build_segments.gd` 데이터 → 씬 다시 만듦):
  - 옥상 A 끝 연사병 → 근접 (물탱크 총잡이와 체크포인트 바로 앞에서 겹침)
  - 옥상 B 높은 옥상 총잡이 → 근접 (광고판 연사병 + 척탄병과 300px 동안 겹치던 가장 센 곳)
  - 골목 A 연사병 발판을 오른쪽으로 (총잡이와 처음 같이 나오는 곳 — 겹치는 범위 320 → 128px)
  - 결과: 옥상 십자포화 0, 옥상 위협 점수 3.9 → 3.5 · 3.7 (새로 나온 틈 · 발판 이동이 따로 어려움을 더하므로).
    골목 B · 관문 2 (마지막 시험) 는 그대로 가장 어렵게
